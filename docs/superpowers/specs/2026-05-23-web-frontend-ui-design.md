# YOLO26 健身系统 Web 前端 UI 设计规格

## 概述

将现有 Tkinter 桌面 GUI 重构为 Web 前端，采用高饱和活力型视觉风格，实现实时健身 AI 教练的完整交互界面。

## 技术栈

- **前端框架**: Vue 3 + Vite
- **样式方案**: TailwindCSS + 自定义 CSS（渐变/发光/动效）
- **后端 API**: FastAPI（封装现有 YOLO26 检测 + PoseAnalyzer + ContextEngine + Agent）
- **实时通信**: WebSocket（视频帧 + 评分数据推送）
- **摄像头接入**: 浏览器 MediaDevices API（getUserMedia）

## 视觉设计系统

### 色彩体系

| 角色 | 色值 | 用途 |
|------|------|------|
| 主色起点 | `#ff6a00` (烈焰橙) | 渐变起点、强调色、活跃状态 |
| 主色终点 | `#ee0979` (玫红) | 渐变终点、次强调 |
| 背景色 | `#0a0a0a` (深黑) | 页面底色 |
| 面板底色 | `#111111` | 视频区、卡片底色 |
| 成功色 | `#38ef7d` (翡翠绿) | 正确动作反馈 |
| 错误色 | `#ff4d4d` (警示红) | 错误动作、停止按钮 |
| 文字主色 | `#ffffff` | 标题、数值 |
| 文字次色 | `#888888` | 标签、辅助说明 |
| 文字弱色 | `#555555` | 禁用、占位符 |
| 边框色 | `rgba(255,106,0,0.15~0.3)` | 卡片边框，强度随重要性变化 |

### 质感风格：发光渐变卡 (Glow Gradient)

- 深黑底色 + 渐变色微光填充卡片
- 卡片 `background: linear-gradient(135deg, rgba(255,106,0,0.06~0.1), rgba(238,9,121,0.03~0.05))`
- 边框 `border: 1px solid rgba(255,106,0, 0.1~0.2)`
- 外发光 `box-shadow: 0 0 25px rgba(255,106,0,0.06), 0 0 50px rgba(238,9,121,0.03)`
- 重要卡片（评分）发光更强，次要卡片（AI对话）发光更弱

### 字体层级

| 层级 | 大小 | 权重 | 用途 |
|------|------|------|------|
| 大数字 | 30-48px | 800 | 总评分（渐变色） |
| 中数字 | 16-18px | 700 | 细分评分、统计数值 |
| 标签 | 10px uppercase | 600 | 卡片标题（letter-spacing:1.2px） |
| 正文 | 11px | 400 | 对话消息、纠错文本 |
| 辅助 | 9-10px | 400 | 分数单位、次要标签 |

### 视频区内嵌灯带仪表

- **实现方式**: CSS `div` 元素，绝对定位于视频容器内壁
- **粗度**: 10px，`border-radius:6px`（圆头）
- **位置**: 左侧竖灯带（角度）、右侧竖灯带（对称）、底部横灯带（时序）
- **轨道**: `background:rgba(255,255,255,0.06)` 作底
- **亮色值**: 渐变色填充 + `box-shadow` 双层发光（14px + 28px）
- **填充比例**: 按评分比例计算高度/宽度（如角度 36/40 = 90%）
- **标签位置**: 角度在左上、对称在右上、时序在左下（次数统计条下方、灯带上方）

### 视频 HUD 叠加层

- 左上: REC 徽章(渐变色) + 动作名称 + 当前相位(绿色边框)
- 左下: 统计条（次数/时长/FPS），`bottom:46px` 避免与时序标签重叠
- 右下: 总评分框，`bottom:30px`，半透明黑底+模糊+渐变边框

### 右侧面板卡片

1. **Score Detail 卡片**（最强发光）
   - 三个环形 SVG 仪表（角度/时序/对称），圆环 + 中央数字
   - 3列统计网格：总次数、训练时长、错误次数（红色）
2. **Correction 纠错卡片**（中等发光）
   - 错误条目：红色发光点 + 错误名 + 建议
   - 正确反馈：绿色发光点 + 正面描述
3. **AI Coach 对话卡片**（弱发光，flex:1 占满剩余空间）
   - 对话消息列表（AI气泡橙底/用户气泡灰底）
   - 底部输入框 + 渐变发送按钮

## 创意交互特性

### 1. 动态响应式 UI

界面随训练状态实时变化：
- **高分状态** (≥80): 视频容器边框发光增强 (`border-color` 透明度提升，`box-shadow` 范围扩大)
- **低分状态** (<60): 发光减弱变暗，边框色偏冷
- **过渡**: 所有变化通过 CSS `transition: 0.8s` 平滑过渡

### 2. 骨骼发光可视化

视频画面上叠加的骨骼不是普通线条：
- **关节点**: 发光圆点，`radial-gradient` + `box-shadow` 外发光
- **正常关节**: 橙色发光，缓慢脉冲动画 (`scale 1→1.3`，2s周期)
- **错误关节**: 红色发光，快速脉冲 (`scale 1→1.5`，0.6s周期)
- **骨骼连线**: 渐变色线条 + 微弱发光阴影
- **实现**: Canvas 叠加层，接收后端推送的关键点坐标绘制

### 3. 动态粒子背景

页面深黑底色上有缓慢浮动的光斑粒子：
- 7-10个粒子，3-6px大小，橙/粉色，30%透明度
- 浮动动画：`translateY` ±30px，8s周期，各粒子不同延迟
- 训练进行时粒子加速（周期缩短到 4s）
- 实现：纯 CSS `@keyframes`，不需要 Canvas

### 4. 形态切换（准备态 → 战斗态）

- **准备态**: 视频中央显示呼吸动画的 "READY — 点击开始训练" 标签，控制条显示大号"开始训练"主按钮
- **战斗态**: READY 标签消失，控制条精简为停止/暂停+动作标签，HUD 信息全部显示，灯带开始填充
- **过渡动画**: 0.6s ease-out，元素淡入淡出 + 缩放

## 数据流与后端接口

### 前后端分离架构

```
浏览器 (Vue 3)                    FastAPI 后端
─────────────────                 ─────────────────
getUserMedia → 视频帧              
    │                              
    ├─ WebSocket ──────────────→  接收帧 → YOLO26 推理
    │                              → PoseAnalyzer 评分
    │                              → ContextEngine 指导
    │                              → ErrorDetector 纠错
    │                              
    ←─ WebSocket ──────────────┤  推送: {
    │                              │  keypoints: [...],
    │                              │  score: {angle, temporal, symmetry, total},
    │                              │  phase: "下蹲中",
    │                              │  count: 12,
    │                              │  errors: [...],
    │                              │  guidance: [...]
    │                              }
    │                              
    ├─ POST /chat ─────────────→  FitnessAgent.chat()
    ←─ Response ───────────────┤  AI 回复文本
```

### API 端点

| 方法 | 路径 | 功能 |
|------|------|------|
| WebSocket | `/ws/detect` | 实时视频帧推送 + 检测结果返回 |
| POST | `/api/chat` | AI 对话（支持远程API和本地模型） |
| GET | `/api/exercises` | 获取支持的动作列表 |
| GET | `/api/history` | 获取训练历史记录 |
| POST | `/api/session/start` | 开始训练会话 |
| POST | `/api/session/stop` | 停止训练会话 |

### 现有评分数据（无需后端修改）

直接从 `AnalysisResult` 获取：
- `score.angle_score` (0-40)、`score.temporal_score` (0-30)、`score.symmetry_score` (0-30)、`score.total` (0-100)
- `count` (次数)、`phase` (当前相位)、`hold_time` (保持时间)
- `errors` (错误列表，含 name/severity/message/suggestion)
- 前端额外计算：训练时长（计时器）、FPS（帧率统计）、错误累计次数

## 控制条与动作切换

- 动作标签从现有 `EXERCISE_STANDARDS` 读取（深蹲/俯卧撑/平板支撑/卷腹/开合跳/引体向上/臀桥/高抬腿/肩推/侧平举）
- 当前选中动作用渐变背景+橙色文字高亮
- 切换动作时通知后端重置评分器状态

## 约束与兼容

- 不修改现有 `code/` 目录下的业务逻辑代码
- 后端仅做 API 封装，调用现有模块
- 优先适配 Chrome/Edge，14-16寸笔记本分辨率
- 摄像头权限由浏览器原生弹窗处理
- 现有 Tkinter GUI (`code/workout_app.py`) 保留不动，Web 版是独立入口
